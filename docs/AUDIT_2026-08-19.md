## Temuan P1

- **Literal `@semua` tidak dirutekan sebagai collective.** Pola collective hanya mengenali bentuk natural seperti `semua, ...` atau `semua ...` di `src/routing/addressing.py:127-153`. Repro: `@semua analisis toko Etsy minggu ini` menghasilkan `NONE`, sedangkan `semua, bantu strategi launch` menghasilkan `ALL_AGENTS`. Ini bertentangan dengan kontrak `@semua` pada PRD v0.3.

- **Targeted cancel tidak membump cancellation generation.** Jalur cancel spesifik hanya mengubah status task dan run di `src/core/orchestrator.py:220-228`; bump generation hanya ada pada global stop di `src/core/orchestrator.py:198-210`. Repro menunjukkan coroutine lama tetap mengirim output dan task dapat berakhir `done` setelah cancel.

- **Pause tidak menghentikan run yang sedang berjalan.** `src/core/orchestrator.py:253-263` hanya mengubah task menjadi `waiting_user`; tidak membump generation dan tidak membatalkan `task_agent_runs`. Repro: status langsung `waiting_user`, run tetap `running`, lalu setelah agent selesai status berubah menjadi `done` dan respons tetap terkirim.

- **Lease event tidak memiliki owner token/generation.** `claim_event()` dapat mengambil alih event expired di `src/core/normalizer.py:31-90`, tetapi `complete_event()` dan `fail_event()` mengubah row hanya berdasarkan event ID di `src/core/normalizer.py:93-118`. Repro: worker pertama claim, worker kedua takeover, lalu completion worker lama tetap menandai attempt kedua sebagai `completed`.

- **Task dependency hanya disimpan, tidak enforced.** `TaskService.update_task_status()` menerima status baru tanpa memeriksa dependency di `src/tasks/service.py:50-55`; tabel dependency hanya menyimpan relasi di `src/storage/schema.sql:20`. Repro: dependent task tetap bisa dimulai dan selesai ketika dependency masih `todo`.

- **Collective execution masih serial.** `src/core/orchestrator.py:343-417` melakukan `await _execute_agent()` di dalam loop role. Repro timing tiga call: sekitar 188 ms dengan pola start/end berurutan, bukan overlap paralel. Ini juga menjadi gap terhadap mode parallel PRD v0.3.

- **Memory scope belum memiliki user boundary.** `MemoryScope` hanya `ROLE` dan `SHARED` di `src/core/types.py:28-30`; explicit save selalu menulis `SHARED` di `src/memory/judge.py:153-161`; schema `memories` tidak punya `user_id` di `src/storage/schema.sql:10`. Memory antar user dalam grup hanya dibedakan sebagai shared group memory.

- **Approval dapat stuck permanen di `executing` setelah crash.** `src/approval/gateway.py:93-126` mengembalikan `APPROVAL_ALREADY_EXECUTING` untuk status tersebut, tanpa lease atau recovery path; schema approval juga tidak menyimpan execution lease di `src/storage/schema.sql:36`. Repro state `executing` menghasilkan retry yang tetap ditolak.

## Temuan P2

- **Terminal task dapat dibuka kembali dan timestamp model tidak berasal dari DB.** Update status unconditional di `src/tasks/service.py:50-55`. `get_task()` tidak mengisi `created_at`/`updated_at` di `src/tasks/service.py:107-113`, sehingga Pydantic memakai waktu sekarang dari `src/core/types.py:155-156`. Repro `done -> in_progress` berhasil dan timestamp model berbeda dari row SQLite.

- **Skill mengiklankan task tools yang tidak terdaftar.** Fallback skill menyebut `create_task`, `delegate_task`, dan `update_task_status` di `src/skills/registry.py:28-37`, tetapi runtime hanya mendaftarkan builtin utility/discovery/browser di `src/tools/builtins.py:103-170`. Repro membandingkan advertised core tools dengan function tools yang tersedia dan menemukan mismatch.

- **Schema tool hanya dikirim ke model, tidak divalidasi executor.** Registry menyimpan/mengirim JSON Schema di `src/tools/registry.py:178-199`, tetapi executor langsung memanggil fungsi di `src/tools/executor.py:75-103`. Repro tool dengan `maximum=5` tetap menerima nilai `999` dan sukses.

- **Markdown memory mirror dapat collision antar group ID.** Sanitasi path di `src/memory/vault.py:12-21` memetakan `team/a` dan `team_a` ke folder yang sama. Repro menghasilkan path `data/memory/team_a/shared.md` untuk keduanya. SQLite tetap terpisah, tetapi mirror dapat saling overwrite.

- **PowerShell setup gagal pada fallback `python`.** `SETUP_MORROW.ps1:15-20` memecah kandidat satu kata dengan range `1..0`, lalu menjalankan `python` sebagai argumen file. Repro PowerShell menghasilkan `python.exe: can't open file ...\python`; setup false-negative jika `py` launcher tidak tersedia.

- **Release builder mengabaikan kegagalan menghapus staging.** `scripts/build_release.py:88-91` dan `:201-202` memakai `shutil.rmtree(..., ignore_errors=True)`. Jika folder staging terkunci, build tidak fail-fast dan berpotensi mengarsipkan file stale dari build sebelumnya.

- **CI belum menjalankan acceptance/live validator.** `.github/workflows/chatgpt-full-fix.yml:31-41` hanya install, launcher smoke, Ruff, dan pytest. Acceptance suite/validator PRD tidak menjadi gate CI.

- **Integrasi PRD v0.3 belum ada di source.** Pencarian source, script, test, docs, dan dependency menemukan tidak ada referensi `OpenViking`, `Immich`, `Microsoft Agent Framework`, `Temporal`, atau feature flag. Dependency runtime masih tercantum di `pyproject.toml:11-27`; role/orchestrator juga masih hardcoded tiga role. Karena PRD v0.3 berstatus Draft, ini dicatat sebagai implementation/roadmap gap, bukan bug v0.2.6.

- **Dokumentasi release terlalu optimistis terhadap gap di atas.** `docs/BUG_BACKLOG.md:5-17` menandai durable event lifecycle dan urgent stop sebagai closed, sementara repro lease race dan targeted cancel masih gagal. `docs/RELEASE_NOTES.md:3-20` menyebut status siap produksi dan collective berjalan independen, sedangkan code masih serial dan pause/cancel belum menghentikan semua run.
